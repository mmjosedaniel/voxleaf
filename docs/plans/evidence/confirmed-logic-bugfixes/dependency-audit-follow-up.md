## Reproduction and bounded correction

The fresh hosted production audit failed when RustSec added
[RUSTSEC-2026-0386](https://rustsec.org/advisories/RUSTSEC-2026-0386.html).
Local `pnpm.cmd audit:release` reproduced the mismatch: eight informational
notices instead of the seven recorded in policy, including Tokio 1.53.1's
unsound Unix `AsyncFd` constructors. Tokio itself is Windows-target reachable;
the affected API is Unix-only. No exception was added to audit policy.

`cargo update --manifest-path apps/desktop/src-tauri/Cargo.toml -p tokio --precise 1.53.3`
selected the upstream patched version. Cargo also resolved existing
`windows-sys` edges for dirs-sys, errno, rustix, tempfile and winapi-util to
already-present 0.59.0 instead of 0.61.2; no other package version changed.
The lock was generated by Cargo, not edited manually. `pnpm.cmd inventory:release`
regenerated the 418-component inventory and lock identity.

The existing release audit is the regression gate: the original lock fails
its Rust stage, and the patched lock passes that stage with the exact unchanged
seven-notice policy. No application API, process boundary, inference,
cancellation, EPUB handling, persistence or audio-buffering policy changes.
The canonical system diagram was reviewed and needs no topology change.

## Remaining optional-runtime audit blocker

The frozen published v5 requirements contain `filelock==3.32.0` and
`setuptools==83.0.0`. Fresh advisory data identifies:

- [filelock CVE-2026-112940 / GHSA-v4x8-3wr5-3wq8](https://github.com/tox-dev/filelock/security/advisories/GHSA-v4x8-3wr5-3wq8), fixed in 4.2.1. The maintainer describes a POSIX SQLite-backed reader/writer-lock issue and explicitly excludes Windows from that path.
- [setuptools GHSA-xmj3-9gf7-h52w](https://github.com/pypa/setuptools/security/advisories/GHSA-xmj3-9gf7-h52w), fixed in 84.1.0. A crafted wheel's namespace metadata can make legacy Windows wheel installation create a fixed-content file outside its destination.

These are package-level audit findings, not proof of exploitability through
VoxLeaf. They nevertheless fail the current audit and are not suppressed.
The published v5 lock, artifacts, native admission and audit policy remain
unchanged. Under ADR-0058, remediation requires a distinct successor assembled
from a hashed lock, compatibility and security checks, actual reviewed package
publication, generated acquisition authority and installed/native acceptance.
A lock-only edit or relabeling the existing v5 environment would not suffice.

Full CI acceptance remains blocked. The earlier completed CLB acceptance and
the approved privacy redaction remain separately scoped evidence.
