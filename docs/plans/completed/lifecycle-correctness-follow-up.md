## User-visible outcome

- After narration finishes naturally, either explicit start action (paragraph leaf or visible passage) starts at the chosen canonical target without an intervening Stop.
- Checking optional Chatterbox status cannot remove temporary files belonging to a newly admitted download.

## Architecture and constraints

Narration retains one identity, scheduler/player pair and bounded in-memory audio. Before an explicit replacement, invalidate old eligibility, join the existing cleanup operation, then start at the canonical target only if the owner/navigation request is still current. Preserve manual save after completion and the latest heard checkpoint; ordinary scrolling must not restart audio.

Optional-package state admission and destructive staging cleanup must be atomic with respect to each other. Use the existing operation/runtime locks with a documented acyclic order. Do not hold an admission lock across network transfer or expensive full-package hashing, and do not nest a helper that reacquires the same mutex. A second unlocked check alone does not close LCF-02.

Termination errors must preserve truthful state and ownership for explicit operations. Best-effort destructor cleanup remains distinct from successful explicit removal. Keep Job Object containment, fixed error codes, bounded waits and existing identity checks. Use the existing optional cleanup failure surface; do not introduce protocol fields.

NSIS cleanup remains limited to existing literal owned roots. A final postcondition must distinguish absence (`FILE_NOT_FOUND`/`PATH_NOT_FOUND`) from inaccessible or unsafe retained data. Continue independent safe cleanup where appropriate, aggregate optional-data failure once, and preserve unrelated files and the independent preference choice. Do not broaden recursive deletion, request elevation or schedule deletion on reboot.

## Risks and rollback

- A completed-run restart may race Stop, close or another target. Use existing operation/revision ownership and delayed-cleanup regressions; do not auto-restart on completion.
- Fixing the staging race can introduce deadlocks or block progress if lock order or critical-section duration expands. Keep cleanup admission atomic and exclude transfer/full hashing from that admission critical section.
- Checked termination must not break best-effort destructor behavior or falsely acknowledge an unknown/foreign service identity. Preserve the existing success/failure controls.
- An uninstall postcondition can mistake deliberately retained data, missing parents or unrelated siblings for failure. Check only the selected data class and exact approved roots; preserve update-mode and silent-default semantics.
- Run filesystem/process regressions only on test-owned synthetic resources; release handles and join threads in bounded cleanup even when an assertion fails. Never delete real optional packages to reproduce a bug.
- Retry a failed gate only after classifying it as a defect, harness/prerequisite problem or environment limitation and making a discriminating correction. A repeated unexplained failure remains pending; do not loop expensive runs.
- Revert only the task-owned unit if a correction cannot preserve its contract. Preserve unrelated changes, prior receipts and original user data; do not reset/clean the repository or rewrite history.
