# Prospective benchmark evidence v1

This maintainer-only contract closes VF-0077 and VF-0091 under [ADR-0076](../architecture/decisions/ADR-0076-prospective-benchmark-safety-evidence.md). It does not change the rejected Qwen product selection or certify new hardware results. Operations are sequential for one operator/session. Do not run preparation, execution, finalization or derivation concurrently for the same session.

## Commands and operator sequence

New official batch v14 and dual-worker v5 requests retain their existing closed fields and additionally require `evidenceVersion: "tts-benchmark-safety-v1"`. Batch also requires its explicit v14 `profileVersion`. Disposable pilots, concurrent diagnostics and historical derivation keep their existing contracts. The exact same official request, including interpreter/artifact paths, commit and prerequisite digests, must be used throughout the prospective workflow. Only its digest is stored in the public binding.

1. Before changing power settings, place the full official request in `$run` and wrap it as `$evidence = @{ family = 'batch'; request = $run }` (use `dual` for v5). Pipe `$evidence | ConvertTo-Json -Depth 8` to `pnpm.cmd benchmark:tts:safety:prepare`. This exclusively reserves the opaque 32-hex session ID and observes the original settings. Inspect `benchmarks/results/raw/safety-v1/<sessionId>/reservation.json` and retain its original values for restoration.
2. The supported manual procedure changes only the standby and hibernate timeout indexes on AC and DC, on that original active scheme. Set all four to zero. Do not change the active scheme, global hibernation availability or other power settings. Tools never write power policy. `pnpm.cmd benchmark:tts:safety:observe` provides a read-only snapshot.
3. Pipe `$run | ConvertTo-Json -Depth 8` to the existing `pnpm.cmd benchmark:tts:batch` or `pnpm.cmd benchmark:tts:dual-worker`. Existing candidate interpreter, offline, clean-tree, exact-host, resource and prerequisite gates still apply. Admission rereads the same scheme and four zero indexes, then exclusively consumes the reservation before acquiring workers. The receipt is `pending-restoration`; it is not derivable yet.
4. Restore the four original values on the original active scheme after either success, failure or interruption. Pipe the unchanged `$evidence | ConvertTo-Json -Depth 8` to `pnpm.cmd benchmark:tts:safety:finalize`. It observes and compares the settings. A mismatch leaves the original evidence intact for retry. An early preflight failure or interrupted run without complete raw can still be finalized, but returns `eligibleForDerivation: false`. A used/finalized ID cannot launch another run; a new attempt starts with a new ID and preparation.
5. Only a completed, restored run can use `$evidence | ConvertTo-Json -Depth 8 | pnpm.cmd benchmark:tts:safety:derive`. It verifies every binding, derives the measurement result privately, deletes the owned `data` directory and confirms its absence before publishing. Failed validation preserves inputs; failed/partial deletion publishes no summary. Restore the original bytes after a read fault before retrying; do not invent replacement observations. Incomplete sessions retain their content-free journal and any partial private data for explicit recovery, never as accepted evidence.

The retained journal is a one-use tombstone under the ignored raw root. Each record is published in full with exclusive ownership. A retry after interrupted publication may finish a missing record using the same verified request and observation. An existing record keeps its original ownership and bytes. `rawSessionRemoved` in the prospective summary refers to removal of its private `data` directory; the original/consumed/settled/restored records intentionally remain. No audio, corpus text, artifact path or interpreter path is included in those records. A failed run does not prove worker containment merely because power restoration succeeds.

## Closed version and bindings

The command wrapper has exactly `family` and `request`, with a 32,768-byte stdin limit. JSON evidence rejects duplicate keys, nonfinite numbers, redirected/reparse ancestors and files over 8 MiB. Unexpected data files fail validation. The code-owned contract is implemented in [benchmark_safety.py](../../services/tts/benchmarks/benchmark_safety.py), with Windows observation in [power_observation.py](../../services/tts/benchmarks/power_observation.py).

Preparation applies the owning official command's complete static validation before native observation or reservation: explicit opt-in, scalar/boolean/path-string shapes, digest syntax and arm/prerequisite relationships. Host, artifact, interpreter and model preflight remain execution-time checks. A prepared reservation is not hardware admission. The same validated request produces the same binding for preparation and execution.

The binding contains exactly `version`, `family`, `session`, `arm`, `execution`, `authority`, `requestSha256`, `cpuBaseline` and `gpuBaseline`. Batch authority is the frozen profile digest; dual authority is its approved authority commit. The full request digest binds all remaining inputs. The journal closes each record to these fields:

| Record | Fields and relationship |
| --- | --- |
| `reservation.json` | `binding`, `original` observation |
| `consumed.json` | `binding`, `admitted` observation, `reservationSha256`; created exclusively before worker construction |
| `settled.json` | `binding`, `files`, `claimSha256`; written only after the complete raw and auxiliary files |
| `restored.json` | `binding`, `observed`, `settledSha256`, `claimSha256`; missing terminal/claim digests are null only for restoration of incomplete/unstarted execution and cannot derive |

Every observation is exactly `at` (positive wall-clock nanoseconds) and `settings`. Settings are the canonical scheme GUID and four unsigned 32-bit indexes: `standby_ac`, `standby_dc`, `hibernate_ac`, `hibernate_dc`. Admission follows the original observation; restoration follows admission. Scheme changes during a native snapshot fail. These observations compare these specific settings, not every possible Windows suspension mechanism. The native read boundary uses [PowerGetActiveScheme](https://learn.microsoft.com/en-us/windows/win32/api/powersetting/nf-powersetting-powergetactivescheme), [PowerReadACValueIndex](https://learn.microsoft.com/en-us/windows/win32/api/powrprof/nf-powrprof-powerreadacvalueindex) and its DC counterpart; it releases the allocated GUID.

Prospective raw identities are `tts-short-segment-batch-raw-v14-safety-v1` and `tts-dual-worker-raw-v5-safety-v1`. They retain the frozen measurement shapes and semantic checks, with pending `sleepSettingRestored: false` and `rawSessionRemoved: false`. Their validators construct a distinct schema in memory; frozen files and historical validator behavior remain unchanged. Raw bytes are never rewritten to claim restoration. Batch binds `raw.json` and `loads.json`. Dual binds `raw.json`, `trials.json` and the exact original bytes of every consumed CPU/GPU baseline. Those baseline digests must match the request, including after capture.

Published output has exactly `schemaVersion`, `binding`, `verifiedDigests`, `measurementSummary`, `powerRestorationVerified` and `privateDataRemoved`. Its version is `tts-benchmark-safety-v1`. Verified digests cover inputs and all four journal records. The inherited measurement summary is nested; export the complete envelope when claiming the prospective guarantees. Legacy commands read separate namespaces and reject these new raw versions. Absence of companion evidence never selects historical acceptance.

## Observed v5 cancellation phases

[dual_worker_trials.py](../../services/tts/benchmarks/dual_worker_trials.py) owns bounded, content-free observations; [the controller](../../services/tts/benchmarks/dual_worker_controller.py) supplies actual admitted/active/completed state. Each trial uses a distinct generation within the session. Its closed proof binds trial, session, generation, admitted occurrences, pending occurrences, adapter entries, a concrete completion if applicable, dispatches, releases, stale rejection and the paired control's releases.

- Before dispatch: admitted occurrences exist, identity invalidates before any submission, and zero work is dispatched or released.
- Queued after invalidation: the third occurrence is still controller-admitted and undispatched when the first two are active. It never dispatches/releases afterward. The paired non-invalidating control releases all three through the same controller.
- Complete before ordered release: a valid waveform's identity, positive bounded sample count, rate and completion timestamps are observed before publication. The real identity gate rejects that particular completion; empty output or an exception cannot satisfy the trial.
- GPU/CPU active: the exact one-unit occurrence reaches adapter entry in its owned child and parks there. Both-active requires both entries parked before one shared invalidation. Entry means adapter entry, not model execution. The existing private two-unit v14 witness remains supported alongside the one-unit v5 occurrence.

The runtime preserves exclusive pipe ownership and exact request/worker identity. Entry barriers are bounded to 20 seconds; existing isolation deadlines also apply. The witness owns termination; runtime cleanup joins that owner before further cancellation. Evidence must include its identity-matching termination receipt. Close releases blocked waiters even on failure. Raw `passed` is derived from the observed phase, no stale release, finite deadlines and no remaining worker; the reader recomputes that projection and rejects contradictory/missing phases, counts, identities, timings or required role evidence. Stale playback here refers to this benchmark's metadata-only path, not physical playback.

Synthetic evidence and the read-only host snapshot are recorded in the [five-search ledger](../plans/evidence/five-search-findings/execution-ledger.md). No new GPU/model, acoustic or live-download result is established.
