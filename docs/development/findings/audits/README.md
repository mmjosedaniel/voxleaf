# Logic-audit history

Use this index with the [registry](../registry.md) and [audit workflow](../README.md).
Read reports relevant to the responsibility or trigger being inspected. Prior
coverage guides the next pass; it does not establish coverage on a later snapshot.

Each completed audit adds one concise, content-safe report using the
[template](../audit-template.md), even when it finds no supported defect. Preserve
completed reports and link new assessments instead of rewriting old conclusions.
An explicit read-only/no-change audit supplies its proposed record in the answer
and does not add a row here.

The 33 imported dispositions remain in the
[historical import](../history-import.md); importing
them or reviewing this workflow is not a new product-code audit.

Add each report with its date, concrete scope, full inspected HEAD and report
link. Put relevant dirty-input identities, coverage, evidence levels and case
IDs in the linked report rather than duplicating those details in this index.
