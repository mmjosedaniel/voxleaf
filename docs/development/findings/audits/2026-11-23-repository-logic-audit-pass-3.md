## Product findings

- [VF-0150](../registry.md#vf-0150) **P3 · The reader says defaults are active while displaying custom appearance.** A failed appearance write retains the value for the session and propagates the failure into the restore cache. After book replacement, an exact or ordinary book-start restore can show “Default settings are active” even while rendering the selected appearance. The existing CAF-R6.2 fixture checks session-only Settings feedback. Extend coverage to the reader notice, the rendered preference after replacement and successful write retry. [Live preference](../../../../apps/desktop/src/App.tsx#L661) · [Notice](../../../../apps/desktop/src/AppPresentation.tsx#L95) · [Replacement fixture](../../../../apps/desktop/src/App.test.tsx#L3521)
- [VF-0151](../registry.md#vf-0151) **P3 · Keyboard focus can move behind Contents in forced-colors mode.** The open panel is followed by reader controls in DOM order. The full backdrop becomes opaque Canvas color, and neither Tab nor the reader skip action closes the panel or excludes the obscured controls. Check traversal past the final available TOC item and the skip action with a real in-book link, then verify visible focus, TOC exit/return and the no-nested-focus-trap policy. [DOM order](../../../../apps/desktop/src/reader/ReaderPublication.tsx#L1294) · [Forced-colors backdrop](../../../../apps/desktop/src/styles/reader-shell-and-settings.css#L405) · [Focus requirements](../../../product/reader-settings-and-playback-controls.md#L601)
- [VF-0152](../registry.md#vf-0152) **P3 · List-item direction is lost before rendering.** An RTL item inside an LTR list can retain RTL on its child paragraph, but the `<li>` itself receives no direction. CSS uses the list item's own direction for the outside marker, so the marker can be on the wrong side. Compare a mixed-direction list with computed item direction, ordered and unordered markers, a neighboring inherited-direction item and unchanged child locators. [Projector](../../../../packages/epub/src/document/xhtml-projector.ts#L1432) · [Renderer](../../../../apps/desktop/src/reader/SemanticDocument.tsx#L403) · [CSS outside-marker rule](https://www.w3.org/TR/CSS22/generate.html#propdef-list-style-position)
- [VF-0153](../registry.md#vf-0153) **P3 · Refill status can refer to an audio section that ended.** With the buffer still below refill threshold, changing from 1× to 0.75× compares against the ended unit's retained active rate. The control says the change will apply after the current section even though it has already ended. Check the visible status and active field during the wait, preserving the genuine active-section pending state, fallback and activation at actual successor start. [Exhaustion](../../../../apps/desktop/src/tts/adaptive-buffer-scheduler.ts#L1107) · [Rate contract](../../../architecture/reader-settings-playback-authority-v3.md#L65) · [Control](../../../../apps/desktop/src/tts/ProductNarrationControls.tsx#L188)
- [VF-0154](../registry.md#vf-0154) **P3 · TTS can still be admitted to spawn during app exit.** When a pending start is verifying a package, the empty child slot lets exit cleanup return while retaining the pending start. If verification finishes before process termination, the pre-spawn guard still admits it. Pinned Tauri invokes the app callback before its own cleanup. The Windows Job is a containment control. The next check should hold verification before spawn, deliver real application exit and observe whether a later spawn occurs, preserving explicit Cancel and already-published termination controls. No orphan or actual process lifetime was established. [Exit](../../../../apps/desktop/src-tauri/src/main.rs#L58) · [Startup](../../../../apps/desktop/src-tauri/src/tts_service_supervisor.rs#L1624) · [Force stop](../../../../apps/desktop/src-tauri/src/tts_service_supervisor.rs#L2105) · [Pinned Tauri source](https://github.com/tauri-apps/tauri/blob/tauri-v2.11.6/crates/tauri/src/app.rs#L1430)
