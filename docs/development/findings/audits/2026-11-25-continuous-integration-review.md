## Redundant work and diagnostics

- **The release job spends most of its time compiling its scanner.** On the audited main revision, installing pinned cargo-audit from source consumed 5m50s of a 7m19s job. The production audit took 30s and inventory verification took 3s. Reuse a verified executable keyed to the scanner version, toolchain and runner. Each run should still refresh advisory data and scan its own locks. [Timed job](https://github.com/mmjosedaniel/voxleaf/actions/runs/45646380329/job/139318383031) · [Install command](../../../../.github/workflows/release-audit.yml#L68)
- **Windows builds the same default Tauri target twice.** PR #333 logged both frontend hooks and two release builds. The first Cargo build took 4m52s and the second took 1m13s. Build once and pass that executable to the smoke script. Running cheap checks before browser and WebDriver setup would also surface the formatting error seen on #332 earlier. That failure took nearly 16 minutes on Windows. [Windows steps](../../../../.github/workflows/foundation-checks.yml#L194) · [Timed Windows job](https://github.com/mmjosedaniel/voxleaf/actions/runs/45547789111/job/138981454378) · [Build hook](../../../../apps/desktop/src-tauri/tauri.conf.json#L9)
- **Ubuntu Rust fetches full Git history and installs the JS workspace to invoke three Cargo commands.** Its script wrappers resolve to Cargo alone. The history-dependent Python validators run in the other two foundation jobs. This Rust job uses the Tauri development configuration and skips JS install scripts. Try a shallow checkout and omit the workspace installation in a fresh Ubuntu run while retaining both Rust feature configurations. Savings were not measured. [Ubuntu steps](../../../../.github/workflows/foundation-checks.yml#L255) · [Configured Rust commands](../../../../package.json#L111) · [Original Linux comparison](../../../plans/evidence/linux-rust-test-repair/README.md#L54)
- **Hosted browser failure evidence disappears with the runner.** Playwright writes failure traces and screenshots locally, and the job has no upload step. A failure-only upload of the synthetic Playwright output with explicit short retention would make hosted-only failures easier to diagnose. [Playwright](../../../../apps/desktop/playwright.config.ts#L29) · [Allowed evidence](../../testing.md#deterministic-foundation-checks) · [Retention policy](../../evidence-retention.md#L30)
- **The action inventory lists four superseded versions.** Its entries for checkout, Node, Python and uv differ from both workflows' pinned revisions. Update the inventory from the pins. The release audit also duplicates the pnpm and cargo-audit versions between workflow and policy. Those copies agree in this checkout. [Documented action versions](../../dependencies.md#L626) · [Foundation pins](../../../../.github/workflows/foundation-checks.yml#L30) · [Release policy](../../../../services/tts/release/audit-policy.json#L4)

## Coverage and limits

- Inspected both workflow triggers and all four job command chains, effective main branch settings, weekly Python update configuration and logs, browser failure retention, native build hooks, ESLint ignore scope, release scanner orchestration and selected inventory claims. The sample includes PRs #332 and #333, the status of six open dependency PRs, the failing jobs on five of them and five v7 updater runs. Repository administration history, individual dependency internals and hosted runner image builds were outside this pass.
- The two Ubuntu jobs test distinct responsibilities. The browser and WebView2 smokes exercise distinct engines. The selected Windows image, host-only benchmarks and GPU/model exclusions have explicit project rationale. Registry VF-0155's original chrono classification is absent in the current generator and inventory. The audit's Rust reachability query omits the release feature, which currently adds no dependency edges. [Foundation scope](../../testing.md#deterministic-foundation-checks) · [Cargo features](../../../../apps/desktop/src-tauri/Cargo.toml#L9) · [VF-0155](../registry.md#vf-0155)
- The release workflow checks pushes, PRs and manual dispatch. Advisory database changes alone do not start a run on idle `main`. This is an interval without a fresh release audit. A periodic gate would be a policy decision.
- The initial index was empty. The initial worktree already contained a PR #333 audit report and edits to the audit index and registry. Their initial SHA-256 values were `dae473f71b9df3dba7537d2ffa627268d1a6592507a06af81f17f669f7498fe7`, `e537e0492b05b837c17b025500bf9560d557722f62025ba5203fd1f649a10448` and `d5db5ed811c830e44ce4de170962902e18f585e74769cd86d6549ec0700a00f5`, respectively. All CI inputs inspected correspond to the identified main HEAD.
- Reconciled the registry, partial historical import, earlier CI coverage, release follow-up and refactor lint evidence. Twelve new case IDs cover one directly observed settings gap and eleven source-supported findings. Past executions or PR output illustrate six of the eleven (VF-0175, VF-0176, VF-0179, VF-0181, VF-0184, VF-0185). One is a distinct key-order variant (VF-0182). There were zero same-ID recurrences and zero new reproductions. Causal origin is unestablished apart from the failure mechanisms documented above.
- Review evidence came from source reads, Git history, `gh run view`, job logs and read-only branch/rules API queries. No tests, workflow reruns, merge attempts or settings changes were performed.
