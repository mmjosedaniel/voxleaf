# ADR-0062: Admit the filelock and setuptools Chatterbox v6 refresh

## Status

Accepted design on 2026-10-23; integration accepted under the revised evidence
boundary on 2026-10-25 local time. The user authorized the three reviewed parts and
continued local integration, preserving previous versions and user data.
Preparation is approved by `CB-V6-PREPARATION-R2-ASTRA-20261024T022500Z`.
The exact three-part prerelease was published on 2026-10-24; its verified
GitHub readback generated the distinct v6 authority. The
[completed ExecPlan](../../plans/completed/chatterbox-filelock-setuptools-security-refresh.md)
records exact local artifact admission, current installed/runtime evidence and
independently approved reuse. Full live acquisition failed twice; its cause
remains unknown. Acceptance does not claim complete live delivery or a transport fix.

## Context

Fresh advisory data rejects filelock 3.32.0 and setuptools 83.0.0 in the
immutable v5 graph. The former advisory concerns POSIX SQLite locks; the
latter concerns legacy wheel namespace installation on Windows. Inclusion
does not establish that an EPUB can reach either vulnerable API.

## Decision

Use a distinct `voxleaf-chatterbox-v6` runtime with filelock 4.2.1 and
setuptools 84.1.0. Preserve the other 77 dependency entries, frozen v3 service
modules, Python/Torch/CUDA identities, six model files, languages and protocol.
V6 requires synchronization from its exact hashed lock before output access.

Bind publication authority to preparation commit
`e46eb99c542b27a891aae6ee20d68c525d79f5f1`, the preparation review above and
the exact archive, runtime manifest and three part hashes recorded in the plan.
An additive authority module preserves historical v5 generator behavior. It
requires actual non-draft prerelease metadata with exact release ID, commit,
tag, asset names, sizes, SHA-256 digests, URLs and uploaded state before writing
any generated authority. Public readback is separate from installed acceptance.

Only `cb/6` may satisfy corrected discovery/execution. `cb/5`, `cb/3`, `cb/2`
and the legacy profile root are cleanup-only. Observation, cancellation and
failed acquisition preserve them. Explicit removal uses existing containment,
reparse-point, busy, termination and runtime-lock guards for those exact roots,
the owned `.previous` backup, and cache/staging roots. Unrelated data is excluded.
NSIS detection and cleanup include both current v6 and retained v5.

Production audit, dependency monitoring, inventory/license evidence, installer
resources, installed harness and size disclosures select the same v6 authority.
Download totals 8,240,302,391 bytes, installed data 8,236,744,319 bytes and
conservative staging 13,271,652,858 bytes. The 20-GB preflight and all existing
transfer, concurrency, memory, cancellation and compatibility limits remain.

## Consequences and alternatives

Publication does not automatically migrate or activate an existing installation.
Corrected use requires an explicit verified acquisition. Historical artifacts,
locks, ADRs and completed plans remain unchanged. Overwriting v5, suppressing
advisories, relabeling an old environment, or executing a retained fallback
would break the identity boundary and are rejected.

The candidate passed real-library security controls and offline ES/EN probes.
The audit retains four explicit URL/CUDA blind spots; the POSIX filelock exploit
was not exercised on Windows. Current B06/B07 regressions, exact local admission,
bilingual installed playback, native recovery, lifecycle, data restoration and
implementation-head CI provide complementary evidence under the revised plan.
V5's real complete journey is historical, not a v6 pass. Exact final review is
required for the documentary closeout. Local inference and ephemeral audio keep the existing
process topology; no public VoxLeaf installer or model asset is published.
